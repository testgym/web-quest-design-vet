# EDU.LAB — педагогічні алгоритми та методики

Інтерактивна навчальна платформа для вивчення педагогічних концепцій і перевірки їх практичного застосування. Працює повністю в браузері: без сервера, бази даних і облікових записів. Інтерфейс створено на Vue 3, TypeScript, CSS і Vite.

## Локальний запуск

Потрібні Node.js **22.18+** або **24.12+** і npm.

```bash
npm ci
npm run dev
```

Vite виведе локальну адресу, зазвичай `http://localhost:5173/`.

## Збірка та перевірка

```bash
npm run type-check
npm run build
npm run preview
```

Команда `npm run build` виконує перевірку типів і створює готовий до розгортання каталог `dist/`. `npm run preview` запускає локальний сервер для перевірки саме зібраної версії. Не відкривайте `dist/index.html` через `file://`: браузерні модулі потрібно подавати через вебсервер.

## Публікація на GitHub Pages

У проєкті є workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml), який після кожного push у гілку `main` встановлює залежності, запускає `npm run build` і публікує `dist/`.

1. Створіть GitHub-репозиторій і завантажте в нього файли проєкту до гілки `main`.
2. У репозиторії відкрийте **Settings → Pages → Build and deployment → Source** та виберіть **GitHub Actions**.
3. Відкрийте вкладку **Actions** і дочекайтеся успішного запуску **Deploy EDU.LAB to GitHub Pages**. Workflow також можна запустити вручну через **Run workflow**.
4. Адреса сайту з’явиться в налаштуваннях Pages і в результаті запуску workflow. Для репозиторію проєкту вона зазвичай має вигляд `https://<username>.github.io/<repository>/`.

У `vite.config.ts` використано `base: './'`, тож зібрані ресурси завантажуються коректно і з кореня домену, і з підкаталогу GitHub Pages. Навігація всередині застосунку не потребує серверних маршрутів.

Для ручної публікації без GitHub Actions виконайте `npm run build`, розмістіть **вміст** `dist/` у корені окремої гілки `gh-pages` і виберіть цю гілку як джерело в **Settings → Pages**. Файл `index.html` має лежати в корені опублікованої гілки, поруч із каталогом `assets/`.

## Структура даних

- `src/data/methods/*.json` містить по одному файлу на методику. `src/data/methods.ts` автоматично завантажує ці файли та експортує масив `methods` у порядку номерів у назвах файлів.
- `src/App.vue` і компоненти `src/components/` формують каталог, теоретичні сторінки, тести та результати з цих даних.
- Результати й прогрес зберігаються в `localStorage` браузера. Відповіді перевіряються на пристрої користувача; запити до API не потрібні. Очищення даних сайту в браузері видалить локальний прогрес.

## Додавання методики

1. Скопіюйте один із файлів `src/data/methods/*.json` до нового файлу в цьому самому каталозі, наприклад `src/data/methods/07-my-method.json`. Префікс номера визначає місце в каталозі. Задайте новий унікальний `id`.
2. Заповніть метадані `id`, `title`, `shortTitle`, `author`, `category`, `difficulty`, `estimatedMinutes`, `duration`, `accent`, `icon`, `heroStat` і `summary`.
3. Додайте `overview` з полями `origin`, `purpose`, `principles` (масив рядків), `caveat`; масив `stages` з полями `id`, `label`, `subtitle`, `description`, `example`; приклад `application` з полями `title`, `scenario`, `steps` (масив рядків), `outcome`; і бібліографію `sources` з парами `label`, `url`.
4. Додайте масив `quiz` із **8–15** завдань. Підтримуються типи `single` і `multiple` (`options` та `correct`), `order` (`items` та `correctOrder`), `match` (`pairs` з полями `id`, `left`, `right`). Кожне завдання має `id`, `type`, `difficulty`, `skill`, `prompt` та `explanation`. Включіть ситуаційні завдання на застосування, а не лише відтворення визначень.
5. Запустіть `npm run build` і перевірте нову методику в каталозі та тесті. `src/data/methods.ts` підхопить JSON-файл автоматично; імпорт або реєстрація вручну не потрібні.

Усі матеріали потрапляють до статичної збірки. Вміст завдань і правильні відповіді доступні в коді сторінки, тож платформа призначена для навчання та самоперевірки, а не для захищеного екзаменування.
